平台前提

CUDA 是 NVIDIA 的并行计算平台，设备代码必须运行在受支持的 NVIDIA GPU 和驱动上。Apple Silicon GPU、AMD GPU 和普通 CPU 都不能直接执行 CUDA kernel。

CUDA 10.2 是最后一个支持在 macOS 上开发和运行 CUDA 应用的 Toolkit 与 NVIDIA 驱动版本；从下一版起不再提供 macOS 支持。因此本文所在的当前 macOS 机器不能用当前 CUDA Toolkit 的 nvcc 编译或在本机 GPU 上运行示例；完整程序需要在安装了匹配版本 NVIDIA 驱动与 CUDA Toolkit 的 Linux 或 Windows 主机上验证。不要把 Clang 能解析一部分 C++ 当成 CUDA 已验证。

Host、Device 与 Kernel

CUDA 程序同时包含两类执行环境：

  • Host：CPU 及其内存，负责分配资源、传输数据和发起计算；
  • Device：NVIDIA GPU 及其内存，执行大量并行线程。

两层错误检查

CUDA 错误至少要在两个位置检查：

  1. cudaGetLastError() 或 cudaPeekAtLastError() 检查非法 launch 配置等立即错误；
  2. cudaDeviceSynchronize()、后续同步复制或 stream 同步检查 kernel 执行期间发生的错误。

只检查 launch 不足以发现越界访问等执行错误，只同步而不检查返回值同样会丢失诊断信息。

Grid、Block、Thread 与 Warp

一次 kernel launch 创建一个 grid。grid 由 block 构成，block 再由 thread 构成：

  • gridDim：grid 在三个方向上的 block 数；
  • blockIdx：当前 block 在 grid 中的三维索引；
  • blockDim：每个 block 在三个方向上的 thread 数；
  • threadIdx：当前 thread 在 block 中的三维索引。

这些内建变量都是三维结构，可访问 .x、.y、.z。执行配置使用 dim3：

Block 不只是逻辑分组。一个 block 会被调度到同一个 Streaming Multiprocessor（SM）上，它的线程可以使用 block 级同步和共享内存。不同 block 必须能够独立执行，调度顺序也不应被程序依赖。

Warp

SM 以 warp 为基本执行批次。在当前 CUDA 编程模型中，warp 大小可通过 cudaDeviceProp::warpSize 查询，NVIDIA CUDA GPU 通常为 32 个线程。

同一 warp 中的线程如果在条件分支中走不同路径，会产生分支分歧：硬件需要分别执行各路径，再屏蔽不参与该路径的线程。Warp 不是 Grid/Block API 层次中的另一个可配置维度，但会直接影响性能设计。

NVCC 与设备能力

nvcc 是编译驱动。它协调 Host 编译器处理 Host C++，并把 Device 代码编译为 PTX 和/或特定架构的二进制代码，最后组合进可执行文件。实际产物取决于 -arch、-code、是否启用可重定位设备代码等选项，不能概括成每次都固定经历完全相同的单一路径。

Compute Capability 描述设备支持的架构特性和若干资源限制。它不是简单的“速度等级”，也不能替代对寄存器、共享内存、occupancy 和访存行为的实际测量。

内存管理

最基础的显式内存流程是：

  1. Host 准备输入；
  2. cudaMalloc 分配 Device 内存；
  3. cudaMemcpy(..., cudaMemcpyHostToDevice) 上传；
  4. 启动 kernel；
  5. 检查 launch 并同步；
  6. cudaMemcpy(..., cudaMemcpyDeviceToHost) 下载；
  7. cudaFree 释放 Device 内存。

需要特别注意：

  • cudaMalloc 的大小单位是字节；
  • cudaMemset 按字节填充值，适合清零，但不能用它把 float 数组设置为任意浮点数；
  • 普通 std::vector 使用 pageable Host 内存；cudaMallocHost 可分配 pinned memory，常用于更高吞吐的异步传输，但会占用稀缺的页锁定资源；
  • cudaMallocManaged 提供 Unified Memory，简化地址管理，但数据迁移成本仍然存在，并不自动保证更快；
  • kernel 可以访问寄存器、local memory、shared memory、constant memory 和 global memory；“kernel 只能访问 GPU global memory”并不准确。

生产代码应让所有成功分配的资源在错误路径上也得到释放。C++ 中可用 RAII 封装 Device 指针。

常见错误清单

  • 把 threadIdx 当成整数，而忘记访问 .x、.y 或 .z；
  • 二维矩阵只检查列、不检查行；
  • 认为 launch 返回就表示 kernel 已执行成功；
  • 固定写死设备上限，不查询 cudaDeviceProp；
  • 把 cudaMemset(pointer, 1, bytes) 理解成把所有 float 设为 1.0F；
  • 用元素数代替 cudaMalloc、cudaMemcpy 所需的字节数；
  • 错误路径提前返回，遗漏 cudaFree；
  • 假设 Unified Memory 没有迁移和同步成本；
  • 在没有受支持 NVIDIA GPU 的 macOS 上把 CUDA 示例描述为“已运行验证”。
