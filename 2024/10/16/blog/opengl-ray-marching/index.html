阅读目标

本文分成两条相互关联、但渲染方式不同的路线：

  1. 使用 GLFW 创建窗口和 OpenGL 上下文，用 GLAD 加载函数，再通过 VAO、VBO、EBO、着色器和纹理完成光栅化。
  2. 使用 ShaderToy 编写片段着色器，通过符号距离函数（Signed Distance Function，SDF）和 Ray Marching 逐像素生成三维画面。

前半部分解释桌面 OpenGL，后半部分解释 ShaderToy 的 WebGL/GLSL ES 环境。两者的 GLSL 入口、版本声明和可用 API 不完全相同，不能不加修改地互相复制。

macOS 环境约束

Apple 从 macOS 10.14 起将 OpenGL 标记为 deprecated。macOS 系统 OpenGL 框架最高提供 OpenGL 4.1 Core Profile，因此：

  • 请求上下文时不能把版本写成 4.2、4.3 或更高；
  • 不能使用 OpenGL 4.3 才进入核心规范的 Compute Shader 等功能；
  • Apple 平台需要设置 GLFW_OPENGL_FORWARD_COMPAT；
  • Apple Silicon 并没有改变上述 API 上限。若新项目需要现代图形或通用 GPU 能力，应评估 Metal、Vulkan 转译层或跨平台抽象库。

本文采用 GLFW 3、GLAD 1 风格头文件和 OpenGL 4.1 Core Profile。GLAD 必须按目标版本生成；如果项目使用 GLAD 2，头文件和加载函数通常分别是 <glad/gl.h> 与 gladLoadGL，不要混用两代接口。

窗口、上下文与 GLAD

OpenGL 命令依赖当前线程上的上下文。正确顺序是：

  1. 初始化 GLFW；
  2. 设置上下文版本和 Profile；
  3. 创建窗口；
  4. 将上下文设为 current；
  5. 通过 glfwGetProcAddress 初始化 GLAD；
  6. 才开始调用 OpenGL 函数。

macOS 的 Retina 屏幕中，窗口逻辑尺寸和 framebuffer 像素尺寸可能不同，所以初始 viewport 和回调都应使用 framebuffer 尺寸。

GLAD 不是窗口库，也不是 OpenGL 实现。它只是把当前驱动提供的函数地址加载到进程中；GLFW 则负责窗口、输入和上下文。

三个对象容易混淆：

  • VBO（Vertex Buffer Object）保存顶点属性的原始字节；
  • EBO（Element Buffer Object）保存顶点索引，使多个三角形复用顶点；
  • VAO（Vertex Array Object）记录顶点属性格式、对应 VBO，以及绑定的 EBO。Core Profile 中绘制前必须绑定 VAO。

glBufferData 的最后一个参数是使用提示，而不是强制策略：

  • GL_STATIC_DRAW：上传后很少修改；
  • GL_DYNAMIC_DRAW：会重复修改并多次绘制；
  • GL_STREAM_DRAW：通常每次使用前都会更新。

EBO 的绑定属于 VAO 状态，因此不要在 VAO 仍绑定时随手把 GL_ELEMENT_ARRAY_BUFFER 解绑，否则会把 VAO 记录的索引缓冲清空。

着色器、属性与 Uniform

顶点着色器对每个输入顶点执行。它至少要写入裁剪空间位置 gl_Position，并可以向后续阶段输出颜色、法线或纹理坐标。光栅器会在三角形内部插值这些输出。

片段着色器处理光栅化产生的片段。片段通常对应候选像素样本，但不能简单等同于最终像素：深度、模板、混合和多重采样都可能改变最终结果。

常用环绕模式包括 GL_REPEAT、GL_MIRRORED_REPEAT、GL_CLAMP_TO_EDGE 和 GL_CLAMP_TO_BORDER。

放大过滤只允许 GL_NEAREST 或 GL_LINEAR。缩小过滤还可以选择 mipmap 模式。

Mipmap 是逐级缩小的纹理链。它让远处的小物体使用更合适的纹理分辨率，从而减轻闪烁并改善缓存访问。

Ray Marching：沿射线推进

从相机原点 沿单位方向 发出射线：

Sphere Tracing 每一步查询场景 SDF，并把当前距离作为保守步长。正确的停止顺序是：

  1. 计算当前位置到场景的距离；
  2. 若距离小于命中阈值，则命中；
  3. 否则累加距离；
  4. 若累计距离超过上限，则判定未命中。

不能只在循环结束后根据总路程着色，也不能把“超过最远距离”当成命中。

常见错误清单

  • 在 macOS 请求 OpenGL 4.5 上下文；
  • 在 glfwMakeContextCurrent 之前初始化 GLAD；
  • 把 GLAD 1 的 <glad/glad.h> 和 GLAD 2 的 gladLoadGL 混用；
  • 使用错误的 GLM 路径，例如 <glm/glm/glm.hpp>；
  • 在 C++ 参数列表中混入全角逗号；
  • 在 Core Profile 中没有绑定 VAO；
  • 把纹理对象 ID 传给 sampler，而不是纹理单元编号；
  • RGB 图片却固定用 GL_RGBA 上传，或忽略行对齐；
  • 把 mipmap 过滤枚举传给 GL_TEXTURE_MAG_FILTER；
  • 声称宽屏中经比例校正的 uv.x 仍位于 ；
  • 把未归一化平面法向量直接当作精确 SDF；
  • Ray Marching 先累加距离、后判断命中，或没有区分命中与超出最远距离。
